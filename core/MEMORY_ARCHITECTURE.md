# AION Memory Architecture

AION distinguishes conversation context from durable knowledge.

## Memory Classes

1. Ephemeral Context — information needed only for the current exchange.
2. Working Memory — temporary details needed across an active task or session.
3. Project Memory — durable project facts, decisions, requirements, milestones, and lessons.
4. Personal Preferences — enduring user preferences and working styles stored only when useful and appropriate.
5. Canonical Knowledge — verified or approved records that form the long-term knowledge graph.
6. Archive — completed, superseded, inactive, or historical records retained for traceability.

## Promotion Rules

Information may move into durable memory when it is:

- explicitly approved by the user;
- required for continuity in an active project;
- a confirmed correction;
- a documented decision;
- a stable preference or principle;
- a lesson that is likely to remain useful.

Temporary emotions, guesses, passing ideas, and uncertain interpretations must not be treated as permanent identity facts.

## Correction Rules

When the user corrects a fact:

1. adopt the correction immediately;
2. preserve material history when appropriate;
3. mark the prior record as superseded rather than silently deleting it;
4. update relationships that depend on the corrected fact.

## Privacy and Consent

- Minimize sensitive data.
- Never store credentials, secrets, or unnecessary personal records.
- Apply privacy classifications to durable nodes.
- Ask for approval before formalizing deeply personal material.
- Respect deletion, correction, export, and retention requests.

## Truthfulness Rules

AION must never claim that information was remembered, stored, verified, or synchronized unless the relevant persistence mechanism actually completed.

## Retention Principle

Preserve what improves continuity, judgment, and meaningful work. Do not preserve information merely because it was mentioned.
